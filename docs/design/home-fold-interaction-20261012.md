# 首页切换与折页修正（2026-10-12）

## 输入与问题

本轮依据用户 21:53 两张 Audiora 截图及展开、折叠参考图。原图保存在 `evidence/home-fold-interaction/`，均为修改前证据，没有把它们当作新包验收截图。

- 推荐初始选中时呈圆角，切到“我的收藏”后出现直角蓝底；这是状态切换问题，不能只检查初次渲染。
- 旧选中底片只在选中时获得背景色。安装依赖 RN 0.86 的 `ViewShadowNode.cpp` 确认：只有布局和圆角的节点可以被折叠，新增有意义背景色会改变原生视图结构。截图与该边界的圆角丢失一致，但没有原生渲染跟踪，不能把具体 drawable 缺陷当作已实机证明。
- 页面滚动更新 `HomeOverview` 中的选中状态，带着音乐内容和数据 hooks 重新渲染。跨多个栏目跳转还会依次激活中途栏目；旧选中/未选中字重不同，会改变文字宽度。
- 折页只有主卡宽度范围内的 -18° → -38° 变化。侧页宽度更短，在大部分角度变化前已滑出视口；侧页太窄、与主卡色彩割裂，缺少参考中的连贯书脊。
- 主卡浅紫和白色拾音卡的视觉重心弱。参考值得沿用的是醒目的连续表面与折页层次；Audiora 继续使用自己的主色和真实音乐内容。

## 实现

- 导航保留原吸顶包装分离方案。每个按钮固定挂载非折叠圆角裁切容器、永久主色底片；仅切换底片透明度和文字色。底片也有明确圆角，按钮字重保持一致。触摸目标至少 44dp。
- 选中状态移入独立滚动组件。音乐内容作为稳定 React 节点传入，栏目选择不再重跑外层数据 hooks 或重新构建歌曲内容。只在实际栏目变化时更新状态；请求跳转期间不闪烁中间栏目，手动拖动或原生滚动结束恢复位置跟踪，跳转范围限制在可到达内容内。
- 收藏侧页从复合卡宽度的 24% 增加至 30%，保留真实收藏数量、关联封面及原收藏详情入口。侧页与主卡去除连接处的内圆角，形成连续卡面和书脊。
- 横滑在侧页宽度 75% 内从 0° 折至 -68°；半个侧页宽度时已超过 45°，反向滑动随之展开。用显式平移/旋转链围绕右侧书脊转动，UI 线程直接跟随滚动；保留 Reduce Motion 的无透视降级。关闭这两个卡片的原始边界裁切，并使用非折叠原生动画节点与 Android 硬件纹理。
- 新 `featured*` 语义表面在统一主题派生层定义：主卡用用户主色色相的不透明底，折页略调明暗，拾音用较明显的同色相浅底；分别计算可读前景。没有改写持久化主色、透明度或其它页面颜色，没有引入参考产品橙红品牌色。
- 收藏、历史、拾音真实队列、当前/历史播放、暂停、定时、搜索、榜单和播放器路径保留。

## 验证及限制

- 14 个相关 Jest suites / 137 tests 通过。新增连续四次栏目切换的原生底片结构、实际 RN StickyHeader 包装、数据 hooks 不随栏目重新执行、跨栏目跳转锁定/拖动恢复、短内容边界、前半段折叠/反向展开与降级回归。
- 颜色测试 19 suites / 205 tests 通过，覆盖浅色、深色、紫色/亮色/透明主色、自定义透明表面及实际主卡、折页、拾音卡前景。`test:colors` 增加两个卡片组件的回归入口。
- check:colors、check:ui、check:motion、typecheck:runtime、修改文件 ESLint 与差异空白检查通过。完整仓库 lint 仍有原有 14 errors / 100 warnings，自动产生的无关格式化已恢复；扩展 TypeScript 检查仍有仓库其它位置诊断，本轮修改文件无诊断。
- 测试不执行 Yoga 像素布局或 Android GPU，不证明真实帧率、三维呈现、圆角裁切或音频已验收。遵守 AGENTS.md：预览包在已连接物理手机保留数据覆盖安装、确认精确版本后停止，由用户验收；不自动启动应用、截屏、点击或运行模拟器。

Native visual QA final result: **blocked — pending user acceptance**。
