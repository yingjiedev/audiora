# 首页吸顶导航布局修正 · 2026-10-12

用户提供 homefold.211446 安装后的 21:36 截图：三个频道纵向排列，选中背景撑满一行，首卡及收藏区被推下；本地歌曲主卡与收藏行封面不一致。

![用户提供的问题截图](evidence/home-sticky-fix/01-broken-navigation.jpg)

## 已确认的原因

React Native 当前依赖中的 `ScrollViewStickyHeader` 会将直接子节点的 style 转移给动画外层，并用 `style: { flex: 1 }` 克隆子节点。原来横排、间距都在直接子节点上，包装后真正承载按钮的节点按默认 column 排列。测试使用的 ScrollView mock 没有执行这个原生组件的克隆路径，所以旧用例虽然通过，没有发现此布局错误。

同时歌曲行通过 `resolveArtwork` 优先读取关联封面，顶部直接使用 `music.artwork`。原始封面为空而关联封面有效的本地歌曲，顶部因此显示默认图；收藏折页只取第一首原始封面也存在相同不一致。

检查了前次 Release 产物对应的 Metro source map，导航/折页模块与前次源码一致。布局错误的已确认原因是吸顶包装边界，不是根据截图推测的资源缓存问题。

## 修正范围

- 新增 HomeSectionNavigation：吸顶组件可替换的 style 仅进入外层；内层独立保持横排、40rpx 轴线、间距和按钮排版。三个频道共用一行，文字单行；选中底形按内容宽度，使用受控普通圆角和 60rpx 最小可见高度，独立点击范围至少 44dp。
- 保留章节定位、滚动选择、吸顶、无榜单来源入口、减少动态效果与既有收藏/完整队列功能。折页、封面构图、真实拾音以及音乐库/我的/底部播放器保持。
- 听歌主卡使用既有 resolveArtwork，与公共歌曲行的关联封面优先级一致。收藏折页优先自定义歌单封面，再读取收藏中首个有效解析封面；没有有效图片时仍保留原默认图或音乐图标。
- 原生状态栏和用户主题配置没有修改。没有重置收藏、播放历史或图片关联存储。
