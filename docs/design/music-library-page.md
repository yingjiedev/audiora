# 音乐库样式审查与统一方案

2026-10-11。目标是让音乐库与当前“我的”页、设置页属于同一套视觉体系，保留现有功能，修复审查确认的错误。

## 证据与边界

- [改造前音乐库](evidence/music-library/library-before.jpg)：用户提供的 `f3a1315896222f6cf4c8700d42aa443c.jpg`。
- [当前“我的”页标准](evidence/music-library/my-style-reference.jpg)：用户最新提供的 `d82cad91f876f401f1a7c07d86e43b9a.jpg`。此次以 Audiora 已实现的页面为参考，不继续套用第三方会员卡结构。
- 源码检查涉及 `MusicLibraryOverview`、`MyMusicOverview`、设置的 `SettingSection` / `SettingRow`、公共 `MusicItem`、本地扫描与搜索入口。没有把未见过的在线页、设置页或新版原生截图当作视觉证据。
- 两张图片都是用户输入，第一张是旧实现，第二张是风格参考；均不是本次修正后的截图。新版真机外观由用户安装后验收。

## 逐项差异、原因与修正

| 项目 | 旧音乐库的问题 | 当前“我的”页的设计逻辑 | 已执行的修正 |
| --- | --- | --- | --- |
| 页面对齐 | 左右 24rpx，比“我的”的 40rpx 更靠边；切换页面时标题、卡片与列表轴线跳动 | 标题和内容共用稳定的左右轴线 | 页边距统一为 `spacing.xxxl`，即 40rpx；标题高度沿用 92rpx |
| 信息结构 | 标签、蓝色横幅、分类卡片三次重复“本地音乐”，却没有分别提供清楚的操作层级 | 主卡承载摘要，卡外一行入口承载分类，下面才是内容 | 标签表示本地/在线；白卡表示设备收录数量和扫描/管理；分类改称“歌曲” |
| 配色面积 | 主摘要与选中分类都铺浅蓝底，图标也套浅蓝方块；操作与静态信息的视觉权重相近 | 白色主卡、深色线性图标，蓝色用于局部功能强调 | 摘要使用 `card`；普通图标用 `text` / `textSecondary`；小扫描按钮用 `tonalSurface` / `onTonal`；选中分类用 `active` |
| 分类布局 | 2×2 大卡片占据大量首屏，用户先看到容器，歌曲被推到下面 | 四个入口一行并列、图标尺寸和文字层级一致 | 歌曲/艺术家/专辑/文件夹改为四个开放式图标入口，窄空间可换行；移除四个独立蓝白底框 |
| 本地/在线标签 | 两个标签贴在左右两侧，中间形成无用途的空白，读起来像两个独立标题 | 同类元素有连续的阅读顺序 | 标签向左成组排列，继续使用公共下划线标签栏；支持横向滚动 |
| 字体与权重 | “本地音乐”在横幅、卡片、列表标题多次加粗；歌曲文字又偏小，轻重关系混乱 | 页标题、区标题、内容标题、次级说明各有明确层级 | 页标题 36rpx/700、区标题 30rpx/600；数值适度放大；作者、数量与说明统一次级文字；歌曲排版由公共行决定 |
| 列表样式 | 使用自建小行、重复音乐图标底框，缺少与搜索/收藏共有的右侧操作结构 | 内容优先，减少重复容器，组件跨页面一致 | 复用公共 `MusicItem`：序号、歌名、作者/专辑/音质信息、下一首与更多；不额外包卡片或封面占位框 |
| 留白节奏 | 横幅、分类大卡、标题、列表分别有自己的间距，首屏出现多个重心 | 主卡与快捷入口间隔 36rpx，区标题与内容紧密关联 | 主卡到分类行沿用 36rpx；列表跟随区标题，所有边距/圆角使用现有设计令牌 |
| 组件细节 | 蓝色描边、底框和图标方块叠加，使轻量入口像多层按钮 | 同类内容共用一张卡，分隔线克制，圆角分级 | 主摘要 28rpx 圆角；在线来源共用 22rpx 分组卡，分隔线从文字列开始；分类和歌曲行不增加边框/阴影 |
| 状态与触摸 | 公共标签栏直接使用未校准的 `primary` 文字，点击高度未设 44dp 下限 | 当前项使用可读的语义色，命名和点击区域明确 | 公共标签文字/指示条改用 `active`；两种标签均有名称、选中状态和至少 44dp 宽高；保留原路由与回调 |

旧页不美观的主要原因是：相同信息多次被强调、容器面积超过内容需要、蓝色承担太多层级、页面之间的对齐和字体规则不一致。修正重点是收敛这些规则。音乐库没有照搬“我喜欢/今日收听/活跃图”，因为其摘要内容和任务不同；它沿用相同的布局语法。

设置页继续使用现有 `SettingSection` / `SettingRow` 的中性分组结构。本次没有改写设置密度或功能；库内在线来源分组沿用相同的白卡、内缩分隔线、深色标题和灰色说明原则。

## 代码审查确认的功能错误

以下结论来自旧源码，不仅来自截图。

| 旧行为 | 修正后的行为 |
| --- | --- |
| 首页只取前 6 首歌曲或前 6 个分组 | 本地内容使用虚拟列表，展示完整数据，保留原歌曲对象 |
| 点击歌曲、艺术家、专辑、文件夹都跳到通用本地页面 | 歌曲直接播放；艺术家、专辑、文件夹展开真实成员；返回分类后可继续浏览 |
| 分组名称作为身份，文件夹路径来源不完整 | 使用完整目录和专辑/艺术家身份分组；兼容持久化 `$`、旧符号附加数据、媒体附加数据与可解析 SAF 路径；同名目录不混合 |
| “扫描音乐”只打开列表 | 库页与原本地管理页共用目录选择→导入进度→成功/失败/取消流程 |
| 本地页的放大镜打开在线搜索 | 本地模式搜索本地曲库；在线模式搜索已启用来源 |
| 点某个在线来源仍搜索所有来源 | 传入来源范围，结果标签与请求均限定该来源；来源失效不偷偷回退全局，旧来源延迟响应不污染新范围 |
| 不支持搜索的来源也显示搜索入口 | 转到现有插件管理入口，文案和无障碍提示反映实际能力 |

全部播放与单曲播放使用当前分类的真实成员作为队列。公共行继续提供下一首与更多菜单；原本地管理入口保留搜索、扫描、批量编辑与删除。没有删除播放历史、下载、收藏或插件功能，也没有变更存储结构。

## 后续质量要求

1. 库页和“我的”页共用页边距、页标题和区标题层级；卡片只用于摘要或内容分组，不给每个歌曲/分类再套独立容器。
2. 跨页面歌曲列表继续复用 `MusicItem`；根据场景调整左侧序号和右侧动作，避免再次各写一套字号、间距和背景。
3. 颜色遵循仓库 `COLOR_SYSTEM.md`，不在页面写原始色值；自定义主题保持用户配置。常规状态用 `active`，喜欢用 `favorite`。
4. 测试检查浅色、深色、紫色/青色自定义和透明卡片上的实际合成背景；普通文字至少 4.5:1。颜色测试不能替代未知壁纸上的真机检查。
5. 保留自然高度与换行；44dp 下限约束点击区域，视觉图标可以更小。英文、繁体、较大字体、窄屏和长标题需要用户检查。

## 二次审查：压缩管理信息，加入真实榜单

本轮输入是用户提供的本地艺术家页、在线音乐源页和热搜排行参考图。两页在配色上已接近“我的”，但顶部概览与操作占位偏大、数字强调过度，艺术家标题下空白较大；在线页只有音乐源入口，缺少可直接聆听的内容。参考图的内容是热搜词，本轮只借用横向排行卡的结构，数据来自实际音乐源榜单，不构造热搜、推荐文案或个性化标签。

| 问题 | 本轮处理 |
| --- | --- |
| 顶部与概览占位较大 | 内容顶边从 16rpx 收到 8rpx，主标签上方额外留白收紧；本地数量与设备音乐同排，使用次级文字，取消大号蓝色数字。 |
| 扫描胶囊过高 | 与“我的”新建共用视觉原则：内层至少 32dp 的小胶囊，外层至少 44dp 点击高度；文字自然增高，不用固定高度裁切。 |
| 两级导航重复下划线 | 主标签保留下划线，四分类仅用图标/文字及字重表达选中。 |
| 分类到首项距离过大 | 无操作的区标题不强制占用 44dp；实际返回、播放和分类操作仍保留至少 44dp 点击范围。分类上下间距、行内留白同步收紧。 |
| 图标辨识度不足 | 艺术家用统一圆形占位，专辑优先使用该组已有歌曲封面，文件夹保留线性图标；不将歌曲封面伪装为真实艺术家头像。 |
| 在线大统计卡与三次搜索重复 | 移除大统计卡，音乐源改为一条白色紧凑栏，可切换启用来源；保留全局搜索、当前来源搜索、明确的管理音乐源入口。 |
| 在线页缺少音乐内容 | 白色 28rpx 圆角榜单卡横向滑动，露出下一张；单卡按可用宽度自然展示。卡内是实际前五首、公共无边框歌曲行、轻量播放胶囊和完整榜单入口。 |

### 数据与交互边界

- 榜单目录复用现有 pluginsTopListAtom，按来源隔离并去重目录；只有当前卡和邻卡读取第一页歌曲，滑动后才请求后续卡，预览按歌曲身份去重并最多五首。并发目录请求在新模块内合并。
- 点击预览歌曲或卡片播放按钮替换为该卡真实预览队列，保留榜单来源与上下文。播放按钮的无障碍名称明确“前 N 首”，不声称已加载完整榜单。
- 完整榜单继续进入已有详情页，完整目录继续进入已有榜单页。只提供目录而没有详情能力时不提供预览播放；没有榜单能力时保留搜索及管理入口。
- 来源被停用/移除时只展示当前可用来源；上一来源延迟返回不会进入新来源队列。空目录、空歌曲、失败、加载中分别表达真实状态，失败可重试，不填造排行。
- 主色仅承担真实选中/播放和主要操作；排名前三只用字重强调，普通排行使用次级文字。沿用 useColors、公共 ThemeText、MusicItem 和设计 token，不扩展颜色豁免、存储格式或原生项目。
- 底部内容容器继续由 Home 按 PlayerDock 实际高度让位，本地和在线列表保留底部滚动余量；实际末项可达性仍由用户真机确认。
