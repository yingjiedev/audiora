# Audiora 信息架构诊断与重构方案

> 基于 `0.2.0` 代码库盘点 + 真机（1220x2656）实测截图。
> 关联 Issue：#34（分阶段页面视觉重构）、#21（第一阶段视觉重构）

## 一、结论先行

当前的问题不是"视觉不够好看"，而是**信息架构（IA）失序**：

1. **同一功能在 3–4 个地方重复出现**，且没有一处是"主入口"，用户无法建立心智模型。
2. **三个 Tab 的职责边界互相重叠**："首页"和"音乐库"都在展示榜单，"首页"和"我的"都在展示我喜欢/历史/本地音乐。
3. **已实现的能力大面积未暴露**：下载管理、检查更新、定时关闭等有完整实现却没有稳定入口；`downloading` 是死路由。
4. **存在两套并行的首页布局代码**（`homeOverview` / `sheets`）和两套导航栏文案，靠配置项切换，维护成本翻倍。

重构核心思路：**按"用户意图"而非"数据类型"划分 Tab**，每个功能只保留一个权威入口，把散落能力收敛到设置与"我的"。Tab 名称保留"首页"，但内容聚焦发现新音乐。

## 二、当前结构实测

### 2.1 三个 Tab 的实际内容

| Tab | 页面文件 | 实际渲染内容 |
|---|---|---|
| 首页 | `homeBody/homeOverview.tsx` | Hero 卡片 → 4 快捷入口 → 发现(榜单横滑) → 最近播放 → 继续播放 → 我的音乐(我喜欢/我的歌单/收藏歌单) |
| 音乐库 | `MusicLibraryOverview.tsx` | 内核 Tab：榜单(巅峰榜/地区榜) / 本地音乐(歌曲/艺术家/专辑/文件夹) / 在线音乐(音乐源列表) |
| 我的 | `MyMusicOverview.tsx` | 资料卡 → 4 快捷入口(我喜欢/播放历史/本地音乐/收藏歌单) → 我的歌单列表 |

### 2.2 功能重复矩阵

| 功能 | 首页快捷区 | 首页"我的音乐" | 我的 Tab | 音乐库 | 顶部导航 | 合计入口 |
|---|---|---|---|---|---|---|
| **我喜欢** | ✅ | ✅ | ✅ | — | — | **3** |
| **播放历史** | ✅ | — | ✅ | — | — | **2** |
| **本地音乐** | ✅ | — | ✅ | ✅ | — | **3** |
| **收藏歌单** | — | ✅ | ✅ | — | — | **2** |
| **我的歌单** | — | ✅ | ✅ | — | — | **2** |
| **榜单/发现** | ✅ | — | — | ✅ | ✅ | **3** |
| **推荐歌单** | ✅ | — | — | — | — | 1 |
| **导入歌单** | ✅ | ✅ | — | — | — | **2** |
| **搜索** | — | — | ✅ | ✅ | ✅ | **3** |

> 一个功能最多出现 3 个入口，且彼此之间没有主次关系。用户在首页点"我喜欢"，在"我的"又看到"我喜欢"，会怀疑"这是不是同一个东西"。

### 2.3 首页内部的分裂

`homeBody/index.tsx` 用 `theme.homeLayout` 配置在**两套完全不同的首页**之间切换：

```tsx
if (homeLayout === "overview") return <HomeOverview />;   // 新版：卡片流
return <Sheets header={<>{!hideHomeHeroCard && <HomeHero />}...} />;  // 旧版：歌单流
```

同时 `HomeBodyHorizontal` 是第三套横屏实现。三套首页共享配置项（`hideHomeHeroCard` / `hideHomeOperations`），但只有其中一套真正响应这些配置 —— 配置项语义已经失真。

### 2.4 死路由与未暴露能力

**死路由（已注册、无任何跳转）：**

| 路由 | 页面 | 状态 |
|---|---|---|
| `ROUTE_PATH.DOWNLOADING` (`downloading`) | `src/pages/downloading` | 全仓库仅有 `routes.tsx:75` 一处引用，**无任何 `navigate` 调用** |

**已实现但无 UI 入口：**

| 能力 | 实现位置 | 现状 |
|---|---|---|
| **检查更新** | `i18n: sidebar.checkUpdate`、`checkUpdate.error.*` | 仅有 i18n 文案与类型定义，**无界面**（只有插件级版本校验） |
| **返回桌面 / 退出应用** | `i18n: sidebar.backToDesktop` / `sidebar.exitApp` | 仅有文案，无实现 |
| **当前版本** | `i18n: sidebar.currentVersion` | 文案存在；实际版本号散落在"我的→资料卡"和"设置→关于" |
| **下载管理** | `core/downloader.ts`（1423 行，完整队列/失败重试/通知） | 页面存在但是死路由；**设置页"下载"分组只有路径与音质，没有"管理正在下载"入口** |
| **公告系统** | `entry/bootstrap/bootstrap.ts` | 启动时自动拉取，用户无法手动触发/清除（`checkAnnouncements`/`clearAnnouncements` 文案在 dev 分组定义但入口不明显） |

**i18n 定义但全仓库零引用（6 个）：**

```
toast.announcementCleared / toast.announcementNone / toast.announcementShown
panel.playById.notFound
toast.artistNotSupported / toast.albumNotSupported
```

### 2.5 设置页入口覆盖不全

`settingsOverview.tsx` 只暴露 8 个入口：基本设置、插件管理、扫描本地、主题设置、权限管理、备份与恢复、语言设置、关于。

但**实际存在的设置页远不止这些**：

- `themeSetting/` 下有 8 个子模块：`mode` / `homeDisplay` / `coverStyle` / `fontSetting` / `background` / `backgroundTuning` / `splashImage` / `appearanceTuning` —— 全部塞在一个长滚动页里，无二级索引。
- `basicSetting.tsx` 1203 行，内含 **9 个分组 80+ 个设置项**，靠顶部横滑标签跳转，移动端很难定位。
- 定时关闭（`TimingClose` panel）只在**首页右上角一个闹钟图标**可进入，设置页无入口。

## 三、根因分析

| 问题 | 根因 |
|---|---|
| 功能重复 | 每次新增页面时"就近放一个入口"，没有统一的入口注册表；首页快捷区与"我的"快捷区是两份独立硬编码数组 |
| Tab 职责重叠 | Tab 按"数据类型"（推荐/库/我）划分，但音乐 App 的真实用户意图是"找新歌 / 听我有的 / 管理我的"，二者不对齐 |
| 能力未暴露 | 功能先做核心逻辑（downloader/updater），UI 后补，补的时候没进 IA 评审 |
| 设置页臃肿 | 设置项按"开发顺序"追加，未按"用户任务"重组 |
| 多套首页 | 视觉重构期间新旧并存，旧实现未清理 |

## 四、重构方案

### 4.1 新 Tab 结构（按用户意图划分）

```
┌─────────────┬──────────────┬─────────────────────────────────────┐
│   首页       │    音乐库     │                我的                  │
│  (Home)      │  (Library)   │   (Mine) — 右上角 ⚙ 设置            │
├─────────────┼──────────────┼─────────────────────────────────────┤
│ 搜索         │ 本地音乐      │ 我喜欢                              │
│ 推荐歌单      │ ├ 歌曲        │ 播放历史                            │
│ 榜单         │ ├ 艺术家      │ 我的歌单                            │
│ 最近播放      │ ├ 专辑        │ 收藏歌单                            │
│ 继续播放      │ └ 文件夹      │ 下载管理 ★                          │
│              │ 在线音乐源    │ 备份与恢复                           │
│              │              │ 关于 & 更新 ★                       │
└─────────────┴──────────────┴─────────────────────────────────────┘
     找内容          管我的文件              管我的资产 & 配置
```

关键变化：

1. **Tab 维持 3 个**：首页 / 音乐库 / 我的。**设置保留在「我的」右上角**，不单独开 Tab，避免底部导航被配置入口稀释。
2. **新「首页」替代原旧首页**：只负责"发现新音乐"，移除所有"我的资产"类入口。
3. **「音乐库」收敛为文件与音源管理中心**：本地音乐四种浏览方式 + 在线音源。
4. **「我的」收敛为个人资产 + 配置入口**：我喜欢、历史、歌单、下载管理、备份、关于 & 更新。
5. **每个功能只保留一个权威入口**（见 4.2）。

### 4.2 入口唯一化对照

| 功能 | 唯一权威入口 | 移除的重复入口 |
|---|---|---|
| 我喜欢 | 我的 → 我喜欢 | 首页快捷区、首页"我的音乐"行 |
| 播放历史 | 我的 → 播放历史 | 首页快捷区 |
| 本地音乐 | 音乐库 → 本地音乐 | 首页快捷区、我的快捷区、设置页 |
| 收藏歌单 | 我的 → 收藏歌单 | 首页"我的音乐"行 |
| 我的歌单 | 我的 → 我的歌单 | 首页"我的音乐"行 |
| 榜单 | 首页 → 榜单（+ 音乐库保留浏览） | 原首页顶部"发现"文字 tab |
| 推荐歌单 | 首页 → 推荐歌单 | — |
| 导入歌单 | 我的 → 歌单页右上「导入」 | 首页快捷区、首页继续播放空态 |
| 定时关闭 | 播放页 + 设置 → 播放 | 仅首页右上角闹钟 |
| 下载管理 | 我的 → 下载管理 | 死路由复活 |
| 备份与恢复 | 我的 → 备份与恢复（设置页同步入口） | 设置 overview 平铺项 |
| 检查更新 | 设置 → 关于 & 更新 | 新实现 |
| 搜索 | 全局：首页/音乐库 顶部搜索框 | 我的 Tab 里的搜索图标（冗余） |

### 4.3 首页（发现）新布局

移除 4 个"我的资产"快捷卡片后，页面重心回到内容：

```
┌──────────────────────────────┐
│ 首页                    ⏱ 🔍  │  ← 定时关闭 + 搜索
├──────────────────────────────┤
│ [Hero: 让音乐去更远的地方]      │
├──────────────────────────────┤
│ 推荐歌单             查看全部 → │  ← 唯一的运营位
│ [卡片] [卡片] [卡片]           │
├──────────────────────────────┤
│ 榜单                 查看全部 → │
│ [飙升] [热歌] [新歌]           │
├──────────────────────────────┤
│ 继续播放                      │  ← 提升到首屏可见
│ [封面 + 进度 + 播放]           │
├──────────────────────────────┤
│ 最近播放                      │
│ [横滑 5 首]                   │
└──────────────────────────────┘
```

- 原"快捷入口 4 宫格"删除 → 释放约 164rpx 高度，把"继续播放"上移。
- `HomeHero` 保留，但去掉与"推荐歌单"重复的跳转语义。

### 4.4 设置页重组（入口在「我的」右上角）

```
设置
├─ 播放          与其他应用同时播放 / 启动自动播放 / 默认音质 / 打断处理
├─ 下载          ★ 下载管理（队列） / 下载路径 / 并发数 / 默认下载音质
├─ 歌词          桌面歌词 / 逐字 / 翻译 / 颜色 / 字号
├─ 外观与主题     浅色深色 / 首页布局 / 封面样式 / 字体 / 背景 / 启动图
├─ 存储与缓存     缓存上限 / 清理音乐·歌词·图片缓存
├─ 音乐源与插件    插件管理 / 自动更新 / 懒加载
├─ 权限          存储 / 通知 / 悬浮窗
├─ 备份与恢复      导出 / 导入
├─ 通用          语言 / 历史记录上限 / 开发者选项
└─ 关于 & 更新    版本 / 检查更新 ★ / 开源许可 / 公告
```

- 设置入口保留在「我的」页面右上角（⚙），进入后按主题分组展示。
- 长滚动页改为**分组折叠**或**二级页面**，避免 1203 行单页。
- 横滑标签导航（`FlatList horizontal`）在移动端发现性差，替换为分组标题 + 折叠。

### 4.5 需要清理的技术债

| 项 | 处理 |
|---|---|
| `homeBody/sheets.tsx` + `homeBody/index.tsx` 旧布局分支 | 删除，统一到 `homeOverview` |
| `theme.homeLayout` / `hideHomeHeroCard` / `hideHomeOperations` 配置 | 评估后废弃或明确语义 |
| `HomeBodyHorizontal` | 保留，但需同步 IA 调整 |
| `settingsOverview.tsx` 里的 8 项写死数组 | 抽为配置驱动，供新设置分组复用 |
| `downloading` 死路由 | 复活为"我的 → 下载管理" |
| `MusicLibraryOverview` 内硬编码中文（"榜单"/"本地音乐"/"全部歌曲"/"未分类文件夹"等） | 全部走 i18n |

## 五、实施建议（分阶段）

**阶段 1 — 入口收敛（低风险，先做）**
1. 「我的」页面右上角保留设置入口（⚙）；`settingsOverview` 按 4.4 重组为分组驱动。
2. 我的 Tab 增加"下载管理"「备份与恢复」入口，移除与音乐库重复的"本地音乐"。
3. 收藏歌单 / 我的歌单一处化。

**阶段 2 — 首页瘦身**
4. 删除首页"我的资产"快捷区与"我的音乐"区块。
5. 调整区块顺序，继续播放上移。
6. 删除旧 `sheets` 布局与相关配置项（需数据迁移评估）。

**阶段 3 — 死路由与未暴露能力**
7. 复活 `downloading`，接入下载队列 UI（`useDownloadQueue` 已就绪）。
8. 实现"检查更新"（`compare-versions` 已依赖，`release/version.json` 已有）。
9. 为公告系统补手动入口。

**阶段 4 — 收尾**
10. 清理硬编码中文，补齐 i18n（含 6 个僵尸键的处理）。
11. 补回归测试：入口唯一性、设置分组导航。

## 六、验收标准

- [ ] 三个 Tab 之间**无功能重复**，每个功能仅一个权威入口
- [ ] `downloading` 路由可从 UI 到达，且能展示真实下载队列
- [ ] 设置页所有已实现设置项都有入口，且按主题分组
- [ ] "检查更新"可用
- [ ] 首页单屏内可见"继续播放"
- [ ] 删除旧首页布局代码后无功能回退
- [ ] 硬编码中文清零（`MusicLibraryOverview` 等）
- [ ] 真机验证：竖屏/横屏、浅色/深色、小屏、长文本
